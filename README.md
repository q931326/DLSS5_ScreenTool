# DLSS5_ScreenTool

给**任意图片 / 视频**附加 NVIDIA DLSS5 神经渲染效果的本机应用。图形界面 + 命令行双模式，支持批处理、超分模式、运动矢量，中文路径无障碍。

```
启动方式: 双击 DLSS5_ScreenTool.bat   或   python DLSS5_ScreenTool.py
```
runtime/ —— nvngx_dlssnr.dll 有 165MB，超过 GitHub 单文件 100MB 硬限制，推上去会被直接拒绝；
---

## 一、它是什么

NVIDIA DLSS5 的核心是 DLSSNR（神经渲染，NGX Feature 18）模型——原本只在游戏内实时运行，需要引擎提供运动矢量/深度等数据，且驱动对非白名单应用做了初始化门控（错误码 `0xBAD00001`）。

DLSS5_ScreenTool 的做法：

1. 使用 NVIDIA 官方签名有效的 DLSSNR 运行时 `nvngx_dlssnr.dll`（310.8.0.0，模型内置，来自原 DLSS5Tool 工具）；
2. 通过社区开源的 `dlssnr_bridge.dll`（源自 [comfyui-dlssnr-test](https://github.com/codon2001/comfyui-dlssnr-test) 项目）**绕过驱动核心的门控**，直接调用运行时的 `Init_Ext / CreateFeature / EvaluateFeature`；
3. 图片/视频逐帧送入神经渲染管线，输出增强后的结果。

因此它可以离线处理任何素材——游戏录像、实拍视频、渲染图、官网截图都行。

## 四、参数详解：每个数值意味着什么

### 4.1 风格 `style`（三选一，切换渲染模型）

| 值 | 名称 | 意味着 |
|----|------|--------|
| 0 | 默认 | 标准神经渲染模型，各方面均衡，不确定时用它 |
| 1 | 自然 | 最保守的一套模型，几乎不动影调，只做降噪 + 细节恢复，适合"不能改变画面"的场合（如仿真数据采集） |
| 2 | 电影 | 对比度/质感最激进的一套，会明显加深阴影、增强材质，画面影调会被改变——要视觉冲击选它，要保真别选它 |

### 4.2 强度 `intensity` 0 ~ 2.0（对效果影响最大的参数）

| 数值区间 | 意味着 |
|----------|--------|
| **0** | 关闭增强，输出与原图**像素级一致**（可用于验证管线是否真的在工作） |
| 0 ~ 0.5 | 轻抚：只去压缩噪点/轻微细节恢复，肉眼几乎看不出 |
| 0.5 ~ 1.0 | 标准：官方默认行为，降噪 + 皮肤纹理、发丝等细节重建 |
| 1.0 ~ 1.5 | 明显增强：细节被 AI "重绘"，画质提升肉眼可见，偶有塑料感 |
| 1.5 ~ 2.0 | 全力重绘：纹理细节明显是"猜"出来的，皮肤可能出现蜡感/纹理游动（视频里逐帧闪动），2.0 基本在赌运气 |
| > 2.0 | 桥接层支持到 -1 ~ 2（负值=反向弱化），GUI 限制在 0 起；负值一般无用 |

调法：从 1.0 起步，嫌不够加到 1.5，出伪影再往回收。

### 4.3 本地色调 `local_tone` 0 ~ 2.0（局部明暗重映射）

| 数值区间 | 意味着 |
|----------|--------|
| **0** | 关闭：画面明暗完全跟随原图，AI 只做细节不动光影 |
| 0 ~ 1.0 | 逐步加强局部对比：暗部更沉、亮部更透 |
| 1.0 | 标准平衡点（默认） |
| 1.0 ~ 2.0 | 光影越来越"戏剧化"，接近 HDR 调色感；拉满容易丢中间调层次，暗部细节被压没 |

素材本身光影不好想"调色"时用它；只是想提升清晰度就保持 1.0 或降低。

### 4.4 本地结构 `local_struct` 0 ~ 2.0（边缘 / 细节增强）

| 数值区间 | 意味着 |
|----------|--------|
| **0** | 关闭边缘增强，画面偏"柔" |
| 1.0 | 标准锐度（默认） |
| 1.0 ~ 1.5 | 边缘越来越硬朗，适合建筑/机械/合成渲染图 |
| > 1.5 | 出现"描边感"——物体边缘像被勾了线；如果素材有噪点，噪点会被同步放大 |
| 2.0 | 最大锐化，几乎必然有描边感，仅极糊的素材可一试 |

### 4.5 皮肤结构 `skin_struct` 0 ~ 2.0（仅命令行，GUI 未暴露）

| 数值区间 | 意味着 |
|----------|--------|
| 0 | 关闭皮肤专用重建通道 |
| 1.0 | 标准人像处理（默认） |
| > 1.0 | 人脸/皮肤纹理重建更用力；**非人像素材影响很小**，不用管它 |

### 4.6 Preset 0 ~ 3（引擎内部模型档）

| 值 | 意味着 |
|----|--------|
| 0 | 最轻量档：速度最快，效果最弱，相当于"轻度 DLSS" |
| 1 | 默认档：质量/速度平衡，官方主推 |
| 2 | 更强细节档：配合"电影感"方案使用 |
| 3 | 最强档：细节最多，但**最容易出噪点和高频伪影**，除非素材质量很差否则不建议 |

> 注意：换 Preset 会触发会话重建（不同档是不同模型），连续批处理时同 Preset 更快。

### 4.7 色彩保真 `color_fidelity` 0 ~ 1.0（输出色调向原图回拉）

| 数值区间 | 意味着 |
|----------|--------|
| **0** | 完全接受 AI 输出的色调（默认） |
| 0.2 ~ 0.5 | 补救区：发现 AI 把色调带偏了（偏灰/偏暖/偏色）时加到这里 |
| 0.8 ~ 1.0 | 色调几乎完全拉回原图，AI 只贡献细节——保真最高但可能留下"细节与影调脱节"的怪感 |

这是唯一的"后悔药"参数：效果满意但颜色不对 → 加它，而不是重调其他参数。

### 4.8 超分 `upscale`（关 / 2x / 3x）

| 值 | 意味着 |
|----|--------|
| 关 | 原分辨率直通引擎，只做增强 |
| **2x** | 模拟游戏低内部分辨率：先缩小到 1/2 再立方放大回原尺寸，AI 负责"把糊掉的细节重建出来"。**这是效果最明显的用法**，也是模型真正的主场 |
| 3x | 起点更糊（1/3 分辨率），重建更激进，细节更多但"编造感"更强 |

⚠️ 超分模式下细节是半/三分之一分辨率重建的——**文字、小字 UI、条码等慎用**，会被重绘成"看起来像但不是"的字。仿真的数据采集画面建议保持"关"。

### 4.9 运动矢量 `motion`（仅视频）

| 值 | 意味着 |
|----|--------|
| 关 | 每帧独立处理（纯空域），速度快，但帧间可能轻微闪烁、噪点残留 |
| 开 | 用 Farneback 光流计算真实运动场喂给模型，激活时域累积分量：结果更稳、更干净；代价是速度变慢，且**快速遮挡、镜头切换处可能拖影** |

### 4.10 调参心法

1. **强度是主菜，其他都是配菜**——先调 `intensity`，不满意再动别的；
2. 想要"官网级震撼对比" → 开超分 2x（先糊后重建）；
3. 画面发灰/偏色 → `color_fidelity` 0.2~0.5；
4. 出描边/噪点 → 降 `local_struct` 或 `preset`，而不是降 `intensity`；
5. 影调被改坏 → 换回"自然"风格，`local_tone` 归 0。

### 实测配方（GUI"方案"下拉可直接选）

| 方案 | 参数 | 适用 |
|------|------|------|
| 仿真保真 | 强度 1.0 + 运动矢量 | 仿真数据采集，不改变影调 |
| 细节重建 | 超分 2x + 强度 1.0 + 运动矢量 | 细节最丰富，有轻微软重绘感 |
| 电影感 | 电影风格 + Preset 2 + 强度 1.5 | 视觉冲击最强，会改变画面影调 |

### 输出规则

- 图片 → 同目录 `<原名>_dlss.png`
- 视频 → 同目录 `<原名>_dlss.mp4`（mp4v 编码，GUI 带进度条可中途停止）
- ⚠️ 同一文件跑多组参数会**互相覆盖**（输出名固定），换参数前先改名或移走旧结果

## 六、效果预期（重要）

**DLSS5 的效果与素材质量负相关**——这是模型的训练目标决定的：

| 素材类型 | 效果 |
|----------|------|
| 昏暗/噪点/压缩重的低质素材 | ⭐⭐⭐⭐⭐ 显著（皮肤纹理、发丝、暗部细节明显恢复） |
| 游戏录像 | ⭐⭐⭐⭐ 明显 |
| 合成渲染（如 Isaac） | ⭐⭐⭐ 皮肤/布料材质可见增强 |
| 干净的高清实拍视频 | ⭐⭐ 克制（仅约 1% 像素可辨变化） |

想要官网那种震撼对比？开**超分 2x**——先让画面变糊，再让模型重建细节，这是模型真正的主场。注意超分模式下文字和小字场景慎用（细节来源是半分辨率重建）。

## 七、常见问题

**Q: 提示"Another DLSSNR live session is already active"？**
运行时每进程只允许一个活会话。应用已自动处理；如果你在外部脚本直接调 Bridge API，换会话前必须先 `dlssnr_destroy` 旧的再 `dlssnr_create` 新的。

**Q: 中文路径能处理吗？**
能。OpenCV 本身不支持中文路径，应用内部已做转换（图片走 imdecode/imencode，视频走 ASCII 临时副本 + 处理后移回原位）。

**Q: OpenCV 读不了我的视频？**
确认文件扩展名在支持列表（mp4/avi/mov/mkv/wmv/webm）且编解码器是常见格式（H.264/H.265 最佳）。

**Q: 处理速度？**
RTX 5060 Laptop 实测：1504×1080 视频约 15 秒/265 帧，含光流计算。同尺寸素材连续处理时会话复用，更快。

**Q: 初始化失败 0xBAD00001？**
驱动不支持或版本过旧。确认驱动 ≥ 616.56 且显卡为 RTX 50 系。

## 九、技术原理速览

```
图片/视频帧 (BGR)
   │  [可选] 超分: INTER_AREA 缩小 1/N → INTER_CUBIC 放大回原尺寸
   │  [可选] 光流: Farneback 计算 prev→curr 运动场, 取反后转 fp16
   ▼
RGBA8 (RGB + 255 alpha) ──▶ dlssnr_bridge.dll
                              │  dlssnr_create(runtime, core, w, h, gpu, preset)
                              │  dlssnr_process(color, motion, depth=null, settings)
                              │  dlssnr_restore_color(...)   ← 色彩保真
                              ▼
                    nvngx_dlssnr.dll (DLSSNR 310.8.0.0)
                              │  Init_Ext / CreateFeature / EvaluateFeature
                              │  (直接调用, 不经 nvngx.dll 的 feature 分发门控)
                              ▼
                       神经渲染输出帧 → <原名>_dlss.png / .mp4
```

ProjectID 与社区通用 ID 一致（`7c134ab9-9677-4af5-a2b2-bca943350861`），SDR 素材 `colorTransfer=0`，缺省 depth/motion 由桥接层自动补零引导。
